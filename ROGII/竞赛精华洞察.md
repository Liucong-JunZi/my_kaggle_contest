## 二、核心数据发现

### 2.1 Typewell 的真相

**hengck23--无公开分数--：** 训练集只有 **69 个唯一 typewell**，不是 773 个。

**PC Jimmy--无公开分数--：** 考虑偏移匹配后，整个油田只有 **57 个唯一 typewell**。

> 它们是 "pseudo-typewells"（伪标准井），不是真实垂直井。部分测试集 typewell 可能是训练集的**偏移副本**——如果确认，意味着可以从训练集复制地质信息。

**hengck23--无公开分数--：** dy 在所有井中是**常数**——强烈暗示数据是合成生成的。

### 2.2 构造面深度列（ANCC/BUDA 等）

**Chris Deotte--7.191--：** `ANCC`、`ASTNU`、`ASTNL`、`EGFDU`、`EGFDL`、`BUDA` 和 `Geology` **仅在训练集可用**，测试集没有。数据页面明确写了 "Training only"。

**Nicolas Bridelance--无公开分数--：** 这些列存储的是**负 TVD 值**（与 Z 同坐标系，约 -9500 到 -7500 ft），**不是 TVT**（~11000-12000 ft）。直接对 TVT 画图会完全错位。Z 和 TVT 的相关性 |r| ≈ 0.999，可用线性插值转换。

### 2.3 TVT_input

**hengck23--无公开分数--：** 水平井"已知段"（井口到造斜点 PS）的 TVT 值，水平段为 NaN。训练集和测试集都有，且**同一口井的非空范围一致**。

## 三、最重要的泄漏/先验：dz = dtvt

**hengck23--无公开分数--：**

```python
h_dtvt = np.gradient(h_tvt)   # TVT 的梯度
h_dz   = np.gradient(h_z)     # Z 的梯度
```

- `dz` 和 `dtvt` 在**同一尺度**，长段完全重叠
- 地层平坦处：`dtvt = -dz` **精确成立**
- 只在倾角变化处分歧（每口井约 **15 个控制点**，间隔约 323 行）

**Oracle 表现：**
- `cumsum(-dz - offset)` → **~7.64 RMSE**
- 但选择 offset 很难：已知前缀法 → ~37-39 RMSE，fold-safe 选择器 → ~14.8 RMSE
- **offset 值似乎是一个离散集合**（有限个可能值）
- 暴力搜索 offset × 未来步长候选 → **12.18 RMSE**（单折）

**Tom--~7.0--：** 用离散 offset 的 `cumsum(-dz - offset)` 可达 **7.7 RMSE**。

**sleep3r--无公开分数--：** 精细的 offset-grid oracle 在训练隐藏行上 ~7.64 RMSE。已知前缀 offset 只能到 37-39，说明**选择 offset 是核心瓶颈**。

## 四、Top 选手方法揭秘

### Tucker Arrants--6.650--

> "With the plain jane GBDT models, CV around 11.00 split on well ID and leaderboard around 9.6. A lot of the gap comes from the structural guide vs local matcher decomposition."

- UNet + 合成井预训练，效果 decent

### Tom--~7.0--

- **Bayesian PINN** (pyro)：CV ~9.18
- **SegFormer + soft seg input**：CV ~9.18，fold 最低到 8.68
- **Neural SDE**：forward-stepping curriculum 能让模型开始学习
- **曲率积分 + teacher forcing warm start**
- **微分同胚 warping**（从平线 warping，类似 Vesuvius Challenge）
- **分段修正模型**：用两个分割点 t1、t2 定义多段修正

> "Probably final score would be 3.5 rmse"（oracle 分数，mock test 可验证）

### hengck23--无公开分数--（CNN/MTP 先驱）

**架构演进：**
1. CNN + SDF（有符号距离函数）→ 全局 GR 波形模式
2. Transformer on dz（不用 GR）→ dz 先验
3. Mixture Density Network → 多轨迹假设（类似 k-beam）
4. 暴力搜索 offset × 未来步长

**关键发现：**
- "z prior is much stronger than gr prior"（Z 先验 >> GR 先验）
- 只需要几个 anchor 点纠正 pace，不需要匹配全部 GR
- ROGII StarSteer 专利：US20190106974A1 — 用 Viterbi/beam search + 倾角方程

## 五、领域特征工程

### Matteo Niccoli--无公开分数--

**消融实验（单 LightGBM）：**

| 特征 | Δ RMSE | 说明 |
|------|--------|------|
| Q-3D 弯曲度 (Jing et al. 2022) | **−0.107** | 最有用的领域特征 |
| 有符号钻井方位角 | — | 上倾/下倾区分是真实的 |
| Well-level AEON (Catch22+ClaSP) | **+0.476** | 使模型更差——过拟合跨井噪声 |
| Verde's BlockKFold | 拒绝 | 空间 blocking 太悲观；井是交错分布的 |

**TVT-Z 解耦发现：**
- 全局 TVT-vs-Z 相关：**r = −0.96**
- 单井水平段内平均斜率：**+0.057**（接近零）
- 全局信号是**跨井结构高程**主导，被造斜段几何扭曲
- 基于全局关系的特征需要先解耦才能生效

**推荐 CV 策略：**
- **StratifiedGroupKFold**，按有符号方位角、中位 TVT、空间位置分层
- 不要用 BlockKFold（空间 blocking 太悲观）

### Matteo Niccoli--无公开分数--（Viterbi 追踪实验）

**Viterbi 集成（5 条路径不同平滑度）+ LightGBM：**
- OOF 从 14.806 → 14.346（改善 0.46）
- **LB 几乎不动：14.081 vs 14.082**
- 这是**教科书级 CV 过拟合信号**

**核心教训：**
> ~14 到 ~9 的 5 ft 差距，**不是**更好的 GR-typewell 匹配推断，而是关于添加**第二个独立信息通道**（邻井的空间结构）。

**结构引导 + 局部匹配器模式：**
- 高分公开 notebook 都同时有两者：
  - **结构引导**：邻井地层平面拟合（FormationPlaneKNN）
  - **局部匹配器**：GR-typewell 匹配（NCC、Viterbi、粒子滤波）
- 单独任一个都达不到 sub-10，组合才行

## 七、空间与序列方法

### Amged Alfaqih--无公开分数--（范式转变）

**为什么纯表格模型撞墙：**
- 把 [X, Y, Z, MD, GR] 传入 LightGBM/XGBoost 忽略了物理/空间现实

**序列现实：**
- 用粒子滤波（PF）或束搜索（beam search）把 TVT 当作移动粒子，基于 GR 观测更新状态

**空间现实：**
- 用 cKDTree 空间插值找最近已知井，计算该区域中位 TVT/地层深度
- 将**"空间邻域共识"**作为特征，极大稳定预测

## 九、常见陷阱

1. **提交错误**：确保 notebook 正确生成 `submission.csv`，检查格式、行数、无 NaN/inf
2. **DTW 限制**：标准 DTW 假设单调序列，不能匹配反向索引
3. **GR 匹配条件差**：即使在真实 TVT 处，水平井↔typewell GR 相关仅 ~0.7
4. **不需要匹配全部 GR**：只需要几个 anchor 点纠正 pace
5. **Z 先验 >> GR 先验**：井轨迹几何比 GR 匹配信息量大得多
6. **Notebook 超时**：注意长耗时操作，本地测试推理时间
7. **坐标系陷阱**：ANCC/BUDA 是负 TVD（~−9500），不是 TVT（~11000+）
8. **随机性控制**：重提交分数变化来自特征工程的随机性，不是测试数据变化
9. **GR 缩放陷阱**：z-score 标准化 GR 后，DP/Viterbi 成本函数可能永远不移动（修复：成本函数用原始 GR API 单位）

## 十、完整方法栈（推荐分层）

| 层级 | 方法 | 作用 |
|------|------|------|
| 1. 粗对齐 | 相位相关 / 互相关 | 检测宏观偏移和断层 |
| 2. 锚点检测 | NCC 滑动窗口 (>0.85) | 找地层锚点 |
| 3. 局部弹性对齐 | DTW (Sakoe-Chiba band) | 处理层厚变化 |
| 4. 深度特征提取 | PatchTST / TimesFM encoder | 捕获多尺度地质模式 |
| 5. 空间结构引导 | 地层平面拟合 (cKDTree 邻井) | 区域倾角展平骨架 |
| 6. 序列追踪 | 粒子滤波 / Viterbi / Beam Search | 保持轨迹一致性 |
| 7. 最终回归 | LightGBM / XGBoost | 融合所有特征 |

## 十二、一句话总结

> **这是一个"结构引导 + 局部匹配器"的双通道问题。** 单独依赖 GR-typewell 匹配（DTW/NCC/Viterbi）或单独依赖空间结构（邻井平面拟合）都达不到 sub-10。核心瓶颈是找到正确的地层 offset（似乎是离散值），然后结合 Z 轨迹先验 + 少量 GR anchor 点纠正 pace。
